## 三、为什么卡片改成 `cover`（v7 核心）

**先说结论：这不是 bug，是取舍。** v5–v6 给卡片加的「近方形 → `contain` + 模糊铺底」，
机制**没有坏**（v7 用真实浏览器实测确认：`--bgi` 设上了、`::before` 确实加载了原图做了模糊），
但**观感坏了**。

**实测数字（真实浏览器量的，不是估的）：**

| 项 | 实测值 |
|---|---|
| 卡位尺寸 | `327 × 184`（`aspect-ratio:16/9`）|
| 方图（215×215）经 `contain` 后 | 只有 **184×184** 可见 |
| ⇒ 方图占卡位宽度 | **184 / 327 = 56%** |
| 两侧剩什么 | 一条"脏色"模糊带 |

一屏里**一半满幅、一半脏条** ⇒ 「未适配、很奇怪」就是这个。

**为什么现在选「满幅」而不是「完整」：**

「卡位大小统一」和「图片不裁不切」在数学上**无法同时满足** —— 卡位是固定比例，
图源却有 **1:1**（52jidi 215×215 / 好游 256×256 / 小七 264×264）与 **2.14**（Steam 460×215）两种。只能选一个偏向。

判据是**基线项目怎么做的**：本机 **PC 游戏工作台（game-aggregator）** 的
**主列表卡 `.row-card .th img` 一直是 `object-fit:cover`**；它的 `contain` 只用在
**106px 的小号「同类推荐」横滑卡**上（那里太小，裁切会看不清）。本页卡位 224px+，属主线场景 ⇒ **跟 `cover`**。

**代价（明说，不藏）：** 方图用 `cover` 进 16:9 会**纵向裁掉 43.7%**（215×215 → 只见中间一条），
方图上的标题/logo 可能被切。这是拿"满幅统一"换的，取的就是统一。

> **★ v11 补测（2026-10-15）：这个「44%」不是最坏情况，而是「每一屏必然出现」的情况。**
> 用 CDP 逐张量测 651 张图的容器框与原图后可见：16:9 的「**最狠单张裁切**」在
> 9 个图片容器上**全部恒等于 43.8%** —— 也就是说任何一屏都能挑出被裁掉四成的图。
> 换 3:2 后降到 33.3%。**这是 v11 把卡位改成 3:2 的真实理由**（不是"更看重不裁不切"）。

**想看四档实物对照 → 打开 `图片适配对照.html`**：

```
图片命中浏览器缓存（file:// 本地缓存、回访都算）
  → <img> 的 load 事件在「节点还没插入 DOM」时就已派发
  → onload="reveal(this)" 根本不执行
  → .ready 永远不加 → opacity 卡在 0
  → 图明明加载完了，却一直透明
```

**教训**：**只要让"可见性"依赖回调，就一定会漏**。
jQuery 时代的 `$(img).load()` 同款问题、`decode()` 的引入原因，都是这一条。

**现在的做法**：`img` **直接可见** + `z-index:1` 压在占位 `.ph` 之上；
`.tag` / `.badge-tr` / `.rankno` / `.hsrc` 升到 `z-index:2`。
`reveal()` 退化为**纯优化动作**（只把占位标 `.gone`）—— 它跑不跑，图都看得见：

```js
function reveal(img){
  const ph = img.previousElementSibling;
  if(ph && ph.classList && ph.classList.contains('ph')) ph.classList.add('gone');
  img.classList.add('ready');          // ★v8：已是纯标记，不再有 opacity 规则挂着它
}
```

`syncImgs(root)` 仍在（渲染后对 `complete` 的图补跑一次），但它现在只是**锦上添花**，不再是正确性的必要条件。

**附带：移除 `loading="lazy"`。**
实测无头 Chrome 在 `--virtual-time-budget` 下**懒加载图几乎不触发**（`mEvent` 98 张全 `complete=false`，
而同一批 URL 纯 HTTP 请求全是 200）。它会让无头截图与真实浏览器看到的不是一回事 ⇒ 直接毁掉视觉验收。
单 Tab 最多 153 张图，全量加载可接受。**将来量级放大请换 `IntersectionObserver` 自管，别退回原生 `lazy`。**

**其他三条老规矩仍在：**
- **全站 `no-referrer`** —— 实测带 localhost 来源头时 `tapimg.com` 返 HTTP 567、`gamersky/gcores` 返 403。
- **52jidi 封面 `/sz/src` → `/sz/420`** —— 实测 140×140（7,668 B）→ 215×215（16,467 B）；
  `/sz/640|800|1080|0` 全部回落 140×140 ⇒ 420 是当前可得上限。
- **详情大图用「库内封面」而非列表缩略图** —— 两者**不是同一张**（128×128 小图铺进 720×250 会放大 5.6 倍变糊）。

## 十、v15：本机三页（游戏库 / 我的游戏 / 下载管理）

用户 2026-10-16 原话：

> 为什么把我工作站给并到了 exe，我需要的是全都能够通过 exe 进行直链下载，最好增加一个功能，
> 下载管理进行统一管理，最好是增加一个我的游戏，可以进行扫盘获取到游戏的启动器，并对应进行匹配，
> 如果能够获取到对应的游戏，则提供下载弹窗（修改器，Mod，存档等），其次游戏还是 demo，数量很少并未实时同步，
> 目前 exe 更像是一个网站，比如 UI 跟组件，能不能进行优化

⇒ **v14 的「PC 工作台入口」（`#hubNav` 5 条外部跳转）被整块移除**，改成三个**本页内**的 Tab。

### 10.1 三个页各自的取数方式

| 页 | Tab key | 取数 | 能否实时 |
|---|---|---|---|
| 游戏库 | `lib` | `/api/library/browse`（分页，total **21,251**；PC 侧 **19,590**） | ✅ 实时 |
| 我的游戏 | `myGames` | **壳侧扫盘** + `/api/library?q=` 按名匹配 | ✅ 实时 |
| 下载管理 | `downloads` | 壳侧 `startDownload` + `shell:dl-progress` | ✅ 本地 |

写法：`TABS` 加三项 → `render()` 开头三条早退分支 → 各自独立渲染函数
（`renderLib` / `renderMyGames` / `renderDownloads`）。这三个页**不走 `D[tab]` 快照数组**
（前 9 个 Tab 都是快照），所以必须有独立入口。

### 10.2 实时层（回答「数量很少、不实时」）

`refreshLive()` 在启动时并发拉 6 路，把结果经 `livePC/liveMOD/liveTR/liveMH` **适配成 demo 卡片形状**
后**就地覆盖** `D.pcNew/pcHot/pcRank/pcMod/pcTrainer/mPlay` —— 其余渲染代码**一行不动**。

```
dlsnapshot 数据.js  →  D[tab]（60/80 条）
                     ↑ 被 refreshLive() 覆盖
上游原始形状        →  livePC/liveMOD/liveTR/liveMH  →  D[tab]（各 300 条）
```

**两条实测口径（很容易想当然，写下来防重犯）**：

1. `/api/library/browse` 的 **`limit` 上限是 100** —— 传 300/500 都只回 100 条（total 照常报 19,590）。
   ⇒ 想多拿必须靠 `offset` 翻页，见 `livePage(path, pages)`：pcNew/pcHot 各翻 3 页 = 300 条。
2. `sort=updated` 的返回**不带 `hot` 字段**（11 个字段），`sort=hot` 才带（14 个字段）。
   ⇒ 「PC 热游榜」取的是 `D.pcHot`（= sort=hot）所以有值 ✅；「PC 新游榜」取 `D.pcNew` 且只要 `dateLabel` ✅。
   两条都不受影响 —— 但**换排序参数时要重新确认这件事**。

### 10.3 我的游戏：扫盘与匹配

壳侧 `scanGames()` 三条来源（**全程只读，不写任何文件**）：

| 来源 | 做法 |
|---|---|
| Steam 库 | 读 `steamapps/libraryfolders.vdf` 拿全部库路径 → 每个库的 `appmanifest_*.acf`（`name`/`appid`/`installdir` 都是明文） |
| 快捷方式 | 桌面 + 开始菜单（含一级子目录）的 `*.lnk`，**只用文件名当游戏名**（不解析 lnk 目标，省掉 COM/WScript 依赖） |
| 常见目录 | Epic / WeGame / Riot / Battle.net / Xbox / Ubisoft 等固定安装根的直接子目录名 |

**不读注册表**：开发期本机沙箱把 `reg.exe` 列入程序黑名单（实测 `PROGRAM BLOCKED BY SECURITY POLICY`），
纯文件系统探测能让「开发期能跑」不再取决于沙箱策略。本机实测两个 Steam 库（`D:\Steam` + `E:\SteamLibrary`）
都是这样解析出来的，命中 `Slotbound Demo`（appid `4906570`）。

**匹配与假阳性防护**：走 `/api/library?q=` 拿候选，**再过 `simName()` 闸门**：
归一化（小写 / 去括号补充 / 去空白与分隔符）后**相等或互相包含**才算命中。
理由：该接口是**模糊搜索**，对任何串都会给「最像的一条」，「设置向导」也能搜出东西来。

### 10.4 ★ 默认视图的取舍：为什么只显示「匹配到资源」的

扫盘会连带捞到大量**非游戏快捷方式**，而且**黑名单永远列不全** —— 本机实测里既有
「7-Zip」「飞书」这种好认的，也有「次元鲨·适配工作台」这种没法用正则认的。

⇒ **判据换成「上游全量库有没有这个名字」**（这才是真的判据，黑名单只当降噪）：

| 轮次 | 动作 | 原始 | 去重后 | 命中资源 |
|---|---|---|---|---|
| 1 | 初版 | 138 | 113 | 7 |
| 2 | 扩充快捷方式黑名单 | 88 | 74 | 7 |
| 3 | 再加「手册/向导/管理器/工具/盒子」 | 79 | **67** | **6** |

页面默认**只渲染命中的 6 条**（`LOCAL.showAll = false`），其余 61 条收在
「显示全部候选 67」开关后面 —— 一个候选都不丢，但默认视图是干净的。

### 10.5 下载：三态入口 + 如实标注边界

`dlBtns(url, name, label)` 统一渲染下载地址，**每个地址给两个动作**：

| 链接形态 | 推荐动作 | 次要动作 |
|---|---|---|
| 真直链（`.zip/.rar/.7z/.exe…`） | **⬇ 客户端下载**（交壳内置下载器，登记进「下载管理」） | 浏览器打开 ↗ |
| 网盘分享页 | **☁️ 转存下载**（复制链接 + 唤起本机客户端，状态标「需手动转存」） | 浏览器打开 ↗ |
| 无壳（浏览器 / 线上 demo） | ⬇ 下载 / ☁️ 复制链接（不走壳） | 同上 |

⚠️ `data-dlstart="1"` **必须带值** —— 委托里判的是 `if(b.dataset.dlstart)`，
写成空属性时 `dataset.dlstart === ''` 是 **falsy**，按钮会「点了没反应」。

**边界（必须如实说，不能吹成「什么都能直下」）**：MOD 的 200 条链接实测
**迅雷网盘分享页 199 条**、百度 1、夸克 1。源站没给直链的，壳也变不出来 ⇒ 这类明确标「转存」。
两处确凿的真直链：游侠存档 `files.direct`（`patch1.ventacorius.com/…rar`）、
FLiNG 修改器上游代理（直连 `flingtrainer.com` **无 Referer 实测 403**）。

### 10.6 桌面客户端形态（回答「exe 更像是一个网站」）

**全部收在 `html.has-shell` 作用域下**（class 由 JS 在探到壳桥时挂上）——
线上 demo 保持网页形态，两边各自符合预期，不会让线上 demo 变成「假桌面应用」。

| 项 | 做法 |
|---|---|
| 自定义标题栏 | 壳侧 `titleBarStyle:'hidden'` + **`titleBarOverlay`**（系统继续画三个窗口按钮）；页面侧 `.topbar` 加 `-webkit-app-region:drag` + `padding-right:142px` |
| 窗口按钮配色 | 系统绘制 ⇒ 不跟 CSS 变量。页面用 `MutationObserver` 观察 `data-theme`，经 `shell:setTitlebar` 同步（**不去改 `applyTheme()`**，否则它会提前引用 `SHELL` 踩 TDZ） |
| 详情 | 从「全屏遮罩 + 居中大卡」改成**右侧抽屉**（`justify-content:flex-end` + 满高 + 从右滑入） |
| 滚动条 | `::-webkit-scrollbar` 收细，thumb 用 `var(--line)`（两套主题自动跟随） |

**为什么不用 `frame:false`**：那样要自己补窗口缩放、双击最大化、键盘快捷键一整套原生行为；
`titleBarOverlay` 则全部保留（本项目 Electron 39.8.10 支持）。

### 10.8 本轮踩的两个「基础设施级」坑（见 PACK §十四.8 有完整表）

1. **下载器漏写文件 ⇒ 下出来 0 字节且不报错**：`res.on('data')` 里只累加了 `got`、忘了 `out.write(c)`。
   是壳的 `--smoke` 自检打出「完成 0 B」才发现的。⇒ 自检要断言**落盘字节数**，不能只看「没抛异常」。
2. **反证脚本就地改写 `index.html`** ⇒ ① 中途被打断就留下打坏版（本轮实际发生）；
   ② 跑的过程中有人编辑 `index.html`，还原那步会把编辑抹掉（本轮也实际发生）。
   ⇒ 根治：`_t_demo.js` 支持 `T_DEMO_HTML`，反证只写 `_mut.html`，末尾打印 `index.html` 的 md5 自证未被写入。

### 10.9 ★ 收尾复拍又抓到一处口径（2026-10-16）

**现象**：顶栏常驻「实时库已接入 · PC 侧 **1520** 条」，侧栏却是「游戏库 **19590**」。

**两个数字都对，但口径不同**：

| 数字 | 含义 | 来源 |

**问题**：两个数字**挨着显示**，会被读成「库变小了」—— 讽刺的是，这一轮修的正是
「顶栏别乱说话」（§10.2 的 `svcPin`：从「闪 4 秒就还原」改成「常驻」）。
