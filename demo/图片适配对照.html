端游卡片图片适配 · 四档对照

同一批真实封面（上排 4 张 = 52jidi / 小七 1:1 方图；下排 4 张 = Steam 460×215（2.14）宽图）， 在四种容器做法下的实际观感。前两排是重点对照，请直接看方图那一排的差别。
为什么会有这个取舍：「卡位大小必须统一」和「图片不裁不切」在数学上无法同时满足 —— 卡位是固定比例，图源却有 1:1 与 2.14 两种。只能选一个偏向： 偏统一 → 用 cover 满幅铺满（方图被纵向裁）；偏完整 → 用 contain 完整显示（方图两侧留空）。

A · contain + 同图模糊铺底

v5–v6 旧做法 · 已废弃
方图两侧用「同一张图放大 + blur(16px) + 55% 透明」填满。 实测问题：模糊底再像原图也只是一块脏色条，一屏里一半满幅一半脏条。 你的反馈「很奇怪、未适配」指的就是它。

B · contain + 浅灰衬底

PC 工作台「同类小卡」的做法
方图两侧用纯浅灰（#f1f3f8）衬底。脏条没有了，比 A 干净得多， 但方图依然只占 56% 宽，仍然「没铺满」。 工作台只用它来兜 106px 的小横滑卡 —— 那里太小，裁切会看不清。

C · 16:9 卡位 + cover 满幅

v7–v10 曾用 · 已被 v11 取代
与 PC 工作台主列表卡 .row-card .th img{object-fit:cover} 完全一致的做法。 满幅、整齐、一屏统一。代价见下表：方图纵向裁掉 43.7%（方图上的标题/logo 可能被切）。

D · 3:2 卡位 + cover 满幅

★ 本 demo 现行（v11 · 混源 Tab）
同样是 cover 满幅、同样统一，只把卡位从 16:9 拉高到 3:2。 方图裁切量从 43.7% 降到 33.3%；代价是宽图两侧多裁一点（16.9% → 29.9%），且卡片整体变高。
