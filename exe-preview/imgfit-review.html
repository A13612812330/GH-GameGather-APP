三、首页右小卡：唯一会「随窗口漂移」的容器机制缺陷

它是全站唯一没有定比的图片容器 —— .hsitem{flex:1;min-height:0}， 高度由 .hero 剩多少决定，而 .hero 的高度又取决于 .hpic{flex:0 0 52%;max-width:560px} 这个组合随窗口宽度的非线性变化。

漂移根因：.hpic{flex:0 0 52%;max-width:560px} —— 主区内容宽超过约 1077px 后，max-width:560px 开始生效，.hpic 宽被锁死、 高度随之锁死；在此之前它跟着 52% 线性变化。这个「悬崖」正好落在 1500~1600 之间， 所以 1440 与 1600 相差 0.3 个比例单位。
这条比第一条更该修：「卡位大小必须统一」是本项目的既有决策，而首页小卡的卡位 根本不一致 —— 换个窗口宽度，同一张图就被多裁 20 个百分点。 exe 窗口若默认 1280 宽，首页看到的正是最惨的那一档。
试过三种「改填充方式」的解法，都不成立（实拍为证）：
现行cover + center
contain + 深色衬底❌ 两侧各留 65px 黑边，像字幕
cover + position 25%❌ 一张改善、一张更糟
所以结论是：填充方式治不了这个病，只能改容器比例。 一刀切的 object-position 依赖「封面主体偏上」这个前提， 实测《赛博朋克2077》因此变好、《生化危机9》反而更差 —— 不可推广，已排除。

五、三个可选方案

方案做法最狠裁切代价
甲 · 全局 3:2 未采纳 把 --th-ar 从 16 / 9 改成 3 / 2，一处改动，全部 Tab 生效 43.8% → 33.3% 卡片高 +18.5%（126px → 149px）；
pcNew 会从 16.9% 恶化到 29.9%（它全是宽图，本来就合适）
乙 · 按源自适应 ★ 已采纳 单源宽图的 pcNew 保持 16:9；其余混源 Tab（pcHot/pcRank/pcTrainer/pcMod/mPlay/home）改 3:2 43.8% → 33.3% 不同 Tab 卡位比例不同（但项目里本来就有 16:9 / 16:10 / 1:1 三套，不算新增复杂度）；
需多看一个 CSS 变量
丙 · 只修首页小卡 已采纳（收窄 240px 版） 不动 --th-ar，只给 .hsitem 定比（连带 .hpic / .hero 高度契约要调） 48~57.8% → 37.5% 只治首页；其余 8 个 Tab 的 33–43% 裁切全部保留
我的建议：乙 + 丙 一起做。 乙解决「每屏都有图被裁四成」，丙解决「首页小卡随窗口漂」—— 两者互不冲突：乙改的是 .cv 系的卡片封面，丙改的是首页 .hsitem。 甲是乙的退化版（少一个判断，但会牺牲 pcNew）。
已排除的做法（别再捡回来）： ① 同图模糊铺底（v5–v6 的 A 方案，用户明确否决过：「很奇怪、未适配」）； ② contain + 浅灰/深色衬底（实测两侧留白 65px，观感像字幕黑边）； ③ 一刀切 object-position（实测一好一坏，不可推广）。

六、改动会碰到什么（影响面）

  • jsdom 断言基线：改动前实测 358 / 358 全绿，改后必须仍是 358/358。
  • 「逐行定高」那套尺寸：--cd-t2 / --cd-meta 是与 --th-ar 配套的，改比例要同步复核卡片总高。
  • 只改 CSS 变量即可生效：.cv 用 aspect-ratio:var(--th-ar)，没有任何 JS 读这个值 ⇒ 不需要改 JS。
  • 不影响打包：这一步在 PACK-GameHub-exe.md 的执行链里排在打包之前，属于「先修再打」的范畴。
